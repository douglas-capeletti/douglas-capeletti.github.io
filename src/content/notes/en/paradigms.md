## What does it mean?

By definition, a paradigm is a mental framework composed of theories, experiences, methods, and instruments that serves to organize thought and, in a certain way, reality and its events. It is the representation of a standard to be followed.

### What about a programming paradigm?

Following the definition of the word itself, a programming paradigm is nothing more than how a programming language structures its parts, providing tools so that programmers can model a system or structure.
Given the structure proposed by the paradigm, it is up to the user of that structure (in this case, the programmer) to choose the paradigm that best suits the problem.

### What programming paradigms exist?

There are several paradigms, some more common than others, and some that coexist within the same programming language.

The most common are:

- Functional Paradigm
- Object-Oriented Paradigm

Others not so common nowadays:

- Event-Driven Paradigm
- Imperative or Procedural Paradigm
- Declarative Paradigm
- Logic or Restrictive Paradigm

There you go, this is the basic idea about paradigms. It's worth noting that not all languages will implement a paradigm to the letter. For example, Golang does not support inheritance, thus not meeting 100% of the requirements of an object-oriented language, but that's okay.
In Java, functional programming was created from an adaptation of the language, not having effective first-class functions but rather "Functional Interfaces"; Java adapts first-class functions to be classes under the hood, and it works. Is it better than Haskell or another functional language? Maybe. Don't get into arguments about which is the best paradigm of all just to compare; it's a waste of time. Try to understand what is best for what needs to be solved.
